# Eval — v1 suite vs v2 research core (2026-10-20)

**Host:** DeepSeek Harness 0.2.1-rc.2, headless profile · **Model:** GPT 6.1 Sol (medium) via 9Router
· **Cases:** 30 (`evals/v2/cases.mjs`) · **Runs:** one per case per arm, plus re-runs of infrastructure stalls
· **Skill arms:** `baseline` = installed v1 suite (71 skills, 64 model-visible) · `v2` = branch `v2-research-core` (57 skills, 9 model-visible)

## Headline

| | v1 | v2 |
|---|---|---|
| Cases passed | 29/30 | 29/30 |
| Input tokens, all cases | 3.98 M | **3.15 M (−21%)** |
| Input tokens, median case | 91.3k | 84.8k |
| Request with no skill needed (R11) | 13.3k | **8.0k** |
| Skill loads, all cases | 60 | 46 |
| Model steps, all cases | 229 | 281 |
| Wall time of final attempts | 1,761 s | 1,691 s |

| Kind | v1 pass | v2 pass | v1 median input | v2 median input |
|---|---|---|---|---|
| routing (12) | 12 | 12 | 164.2k | 125.1k |
| quality (12) | 12 | 11 | 79.2k | 73.8k |
| regression (6) | 5 | 6 | 93.4k | 100.3k |

Accuracy is equal on this suite; the cases are not hard enough to separate the arms on answer
quality. The measured gains of v2 are cost (−21% input tokens), the fixed per-request floor
(−5.3k tokens) and the one regression v1 still fails: **N01**, where v1 overrode the project's
recorded scope ("Ghi chú cũ về mục tiêu NCKH cũng không ngăn mình đánh giá lại theo câu hỏi Q2")
and v2 quoted `NOT to assign any venue band` and declined to grade.

## Where v2 costs more

R04 (+62k), R10 (+18k), R08 (+45k), N02 (+45k), N03 (+19k), N04 (+37k): `evidence-check` and
`research-assess` read `_shared/evidence.md` and `_shared/reasoning-check.md` on most calls, and
hidden skills cost one extra step through `admin`. These are the next optimisation targets.

## Infrastructure stalls

The upstream (Codex via 9Router) twice stopped answering for 5–10 minutes. dsh's stream idle
timeout did not cut these requests, so the runner treats 240 s without any event as a stall,
kills the case and retries it up to twice; stalled attempts are excluded from the table and
their tokens counted separately (v1: 471k, v2: 390k). Both arms got one extra re-run batch for
cases that stalled on every attempt (v1: R02 R03 R08 Q02 Q04 Q05 Q10; v2: R08 Q02).

## Grader corrections (applied to both arms; originals kept in `results.orig.jsonl`)

Made after reading the actual answers, before computing this table:
- **N06** — the regex missed LaTeX forms (`\sqrt{2}`, `1{,}414`); both arms were right. v1 and v2 both changed FAIL → PASS.
- **N01** — the old rule accepted any mention of "NCKH" (which let an answer that overrode the
  scope pass) and flagged a quoted echo of the question ("đủ Q2"). New rule: the answer must cite
  the scope constraint itself, and only an unquoted assignment counts. v2 changed FAIL → PASS; v1 stays FAIL.

Not corrected: **v2 Q02** fails one regex because it wrote "bỏ cả gate lẫn residual" instead of
"cả hai/both"; the answer is correct on reading. Left as a fail to avoid tuning the grader toward v2.

## Limits

- One model, one run per case: no variance estimate.
- Fixtures are small synthetic papers and logs; grading is regex on the final answer.
- Measured on dsh only; Claude Code and Antigravity were not measured.

## Reproduce

```bash
node evals/v2/build-arm.mjs --src ~/.claude/skills --out .tmp/arms/baseline --hide-deprecated
node evals/v2/build-arm.mjs --src .claude/skills --out .tmp/arms/v2
node evals/v2/run.mjs --arm-dir .tmp/arms/baseline --arm baseline --label baseline-r1
node evals/v2/run.mjs --arm-dir .tmp/arms/v2 --arm v2 --label v2-r2
node evals/v2/report.mjs --arm baseline=baseline-r1 --arm v2=v2-r2
```
